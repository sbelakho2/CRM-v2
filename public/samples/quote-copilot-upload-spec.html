BOM Upload Specification

Use this page when you prepare a BOM for the Quote Co-Pilot uploader. It describes the exact web-upload contract, the recommended column layout, and the parser behaviors that make messy BOM exports still acceptable.

Web Uploader Requirements

  • Required form fields: company, destination country, BOM file, board count, and issuing company.
  • Optional form fields: order multiple, pricing providers, incoterms, and notes.
  • Accepted file types in the web form: CSV, XLSX, and XLS.
  • Backend parser support: TSV, TXT, and ODS are supported by the parser service, but they are not exposed in the current web upload control.

Minimum BOM Data Needed

  • Each accepted row must contain at least Part Number or Description.
  • Quantity is expected and is normalized to at least 1.
  • The recommended canonical header set is: Part Number, Description, Quantity, Manufacturer, Reference Designators.
  • The fill-in template uses this canonical header set plus optional sourcing columns.

Recommended Upload Columns

Column Required Purpose
Part Number Recommended Primary manufacturer part number. Best column to provide if you want distributor matching to be reliable.
Description Fallback Used when Part Number is missing and also helps smart fallback searches.
Quantity Yes Per-board quantity before board-count multiplication unless Stock Quantity is supplied.
Manufacturer No Improves confidence scoring and reduces false matches.
Reference Designators No Used for traceability and as a quantity fallback when ranges such as C1-C10 are present.
Package No Useful for passives and footprint-sensitive matching.
Supplier / Supplier Part Number No Preserved for sourcing context and manual review.
Stock Quantity No Overrides per-board quantity when you want pricing based on the actual purchase quantity.
Unit Price No Optional embedded BOM price. Preserved for comparison against live API pricing.
Remark No Can carry substitute or alternative part numbers. The pricing engine can fall back to this when the primary MPN fails.

Parser Tolerance Rules

  • Header row is auto-detected by scanning the first 25 rows.
  • CSV delimiters are auto-detected across comma, semicolon, tab, and pipe.
  • Alias headers such as MPN, Manufacturer Part Number, RefDes, Qty, Count, Brand, and Footprint are recognized.
  • Quantities like x3, 2 pcs, 5 ea, and 2,000 are normalized automatically.
  • DNP, Do Not Populate, Do Not Place, and No Load rows are skipped.

Normalization Before Pricing

  • Duplicate rows are consolidated by normalized part number or description.
  • Reference-designator ranges such as R1-R10 are counted automatically.
  • Board count multiplies BOM quantities before pricing.
  • Order multiple can round quantities up before pricing.
  • MOQ, pack size, and distributor order multiples can increase the effective quantity during pricing.

Preparation Checklist

Before Upload

  1. Keep one BOM line per row.
  2. Prefer real manufacturer part numbers over internal library IDs.
  3. Include manufacturer and package when passives or alternates are ambiguous.
  4. Use Stock Quantity when you want supplier pricing based on total order quantity.

After Upload

  1. Review coverage and confidence warnings.
  2. Check lines where quantity was adjusted because of MOQ or pack size.
  3. Review alternates if a fallback part was used.
  4. Publish only after coverage and lead-time risk look correct.
